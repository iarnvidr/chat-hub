## Chat-first history integration

The current product priority is ChatGPT conversations: a shared local history, individual conversation tabs, local reading and search, and continuing chats. Codex is a secondary source under the optional all-history view; it is not the next feature-development track.

The existing Paseo `chatgpt-history` plugin was located in the infrastructure checkout. Chat Hub now has two adapters: reuse its unchanged OAuth/paging/batching/render pipeline while retaining full raw graphs, and import a consistent read-only snapshot of its existing cache. The first real raw sync returned HTTP 429. The deployed cache snapshot contained 702 ChatGPT, 2,107 local Codex and 7 cloud Codex conversations; all 2,816 were imported into the local library. Source account identity matched the selected local Codex login. Credentials were not copied into the snapshot or exports.

Cached transcripts preserve the plugin's exact text and metadata as archive records, with explicit cached-transcript provenance and distinct provider/account namespaces. They do not claim original message boundaries or alternate branches. Full raw graph ingestion remains separate. The app has individual conversation tabs, preserves selected branches between local tabs, and keeps live new-conversation browsing in the reader area rather than a separate provider window. A native isolated direct-load check reached the public ChatGPT page and verified return to the library plus denial of privileged provider IPC. This does not validate sign-in or a captured live turn.

Local acceptance includes 35 passing Rust test targets, 30 desktop UI checks, 10 bridge/cache-export checks, a production app build/signature check, and authenticated reads/search against the populated library. After separating read-only DB connections from imports, a local list request took 30 ms and a selected cached transcript took 13 ms; these samples are not general performance guarantees. The largest cached transcript still exceeded the bounded detail-response path and needs paged reading. Automatic refresh from the deployed plugin cache, full graph reconciliation, signed-in live capture, and packaged updater acceptance remain open.
