File references are not a promise that their bytes were downloaded: produced files, attachments and mentions are distinguished; metadata and saved content remain separate. SQLite backup includes saved bytes; JSON interchange does not. A private SQLite checkpoint was taken before schema migration 12.

Appearance offers five persistent color schemes (amber, green, blue, violet and light paper), including graph colors. Cmd/Ctrl+W closes only the active tab and is a no-op without tabs, including when the embedded provider view has focus. Other native tab shortcuts are wired through the application menu. Unit and native checks cover these paths; no local browser driver is used.

The local Rust CLI is installed through `build/install-cli.sh` into `~/.local/bin`. Help/version, token-free local library commands, and status discovery of the running desktop service are implemented. Desktop status uses its existing private descriptor/token and verifies the authenticated PID; it reports that verification separately from the standalone service's stronger stored instance-ID check. The installed CLI was checked against the owner app and library: status reports running/healthy, search returns saved matches, and read returns saved JSON. ChatGPT browser sign-in, live fetching and sending remain desktop operations.

The active branch is `codex/direct-chat-service` (PR #28). Chat is the default source; Codex stays behind its own toggle. The application and CI use Rust/Cargo, Bun, Python and Go without a Node runtime. Checks, Security and Apple Silicon packaging passed at `68091ae`; later feature commits need their own CI evidence. Preserve the separate trusted-main and release-gate work.

The local catalog persists a revisioned index of chats, projects, bounded text samples, original messages and parent relationships. The overview uses the vendored MIT Cytoscape.js 3.34.4 browser module with a force layout and compact chat nodes. The map selects up to 100 connected chats across the full scoped index, with degree bounded at four and representation across connected components; isolated and omitted chats remain available in the sidebar. It shows shared project membership or at least two filtered shared terms weighted by rarity. These are lexical suggestions, not semantic similarity claims. Search selects a chat in place; an explicit action expands its full-index neighborhood of up to five related chats. Labels remain readable at zoom and are progressively revealed to avoid overlaps. Message drilldown follows stored parent links and preserves branch navigation. Imported transcripts remain archives; unavailable message boundaries and branches are not invented.

Project names are fetched and acknowledged before full conversation listing, so a subsequent list-stage 429 does not discard those names. Visible, exact same-origin ChatGPT project links can provide a read-only fallback; the authenticated sidebar API remains authoritative. Exact sidebar-observed IDs can update legacy `paseo-chatgpt` / `paseo-cache:*` project titles without changing provider, account scope or membership. Other verified account scopes are left untouched. The connected owner library was checked in the actual native app: existing imported project labels now show their real upstream names and remain persisted locally.

Project assignment supports a user-requested upstream change in the owned ChatGPT WebView and commits the local assignment only after a subsequent read verifies it. Local project labels remain a separate explicit option. Upstream rename now follows the recognized project settings contract, preserves the other settings, and verifies a readback before updating the exact local project row. Unknown settings shapes fail closed. Legacy Paseo rows remain immutable local locators; only the current signed-in ChatGPT session authorizes the upstream action. The bounded passive proxy learner stores normalized operation schemas without values, credentials or raw bodies. No live project mutation was performed during implementation checks.

Fresh ChatGPT history fetching currently encounters HTTP 429 in the connected owner session. Synthetic tests and the existing local archive do not establish successful fresh-history or streamed-capture acceptance. Continue that acceptance work independently of graph presentation. Background CI/release coordination should continue while product work proceeds.

## Chat-first history integration

The current product priority is ChatGPT conversations: a shared local history, individual conversation tabs, local reading and search, and continuing chats. Codex is a secondary source under the optional all-history view; it is not the next feature-development track.

Chat Hub replaces the Paseo history plugin. The app owns fetching, capture, new chats and its local service. A future plugin may connect to this service; no existing Paseo deployment is a runtime dependency. The native history job uses the app's own signed-in ChatGPT webview to fetch lists and complete raw graphs. The provider receives no local service credentials or privileged native IPC. Native code pulls bounded graph chunks, validates account scope and ordering, commits them through the shared importer, then acknowledges the next chunk. Rate limits and partial failures preserve committed progress. Existing local raw import and offline-library prerequisites remain in place.

Earlier migration data contained 702 ChatGPT, 2,107 local Codex and 7 cloud Codex conversations; all 2,816 remain in the local library. Source account identity matched the selected local login. Credentials were not copied into that snapshot or its exports. Those imported transcripts are migration data, not a substitute for direct history fetching. The separate owned OAuth worker received HTTP 429 on a real normal-conversation-list probe; the failure stage is now known, and retries respect the recorded cooldown. Native browser-session fetching and live generation still require real signed-in acceptance.

Cached transcripts preserve the plugin's exact text and metadata as archive records, with explicit cached-transcript provenance and distinct provider/account namespaces. They do not claim original message boundaries or alternate branches. Full raw graph ingestion remains separate. The app has individual conversation tabs, preserves selected branches between local tabs, and keeps live new-conversation browsing in the reader area rather than a separate provider window. A native isolated direct-load check reached the public ChatGPT page and verified return to the library plus denial of privileged provider IPC. This does not validate sign-in or a captured live turn.

Local acceptance includes 35 passing Rust test targets, 30 desktop UI checks, 10 bridge/cache-export checks, a production app build/signature check, and authenticated reads/search against the populated library. After separating read-only DB connections from imports, a local list request took 30 ms and a selected cached transcript took 13 ms; these samples are not general performance guarantees. Follow-up detail budgeting counts actual JSON escaping and normalized part duplication instead of multiplying all source bytes by six. Search now reads only graph topology, with bounded snippets, so large transcript bodies do not prevent hits. Focused tests cover exact large UTF-8 transcript reconstruction and escaping/wrapper budget rejection. Paged reading for detail responses genuinely above 8 MiB remains open.

Recognized saved ChatGPT IDs, including Paseo's `conversation:<UUID>` document IDs, offer **Continue in ChatGPT**. This targets the individual live conversation in the embedded reader, preserves its local tab, and offers **Read saved copy**. Native command targets are constructed from validated UUIDs; arbitrary URLs are rejected. **Connect ChatGPT** provides the account connection flow, and **Save live chats on this Mac** persists capture preferences with an explicit safe restart. These implementations do not establish signed-in sending or capture acceptance. Full graph reconciliation with migrated transcripts, signed-in fetching/capture, and packaged updater acceptance remain open.

Native isolated acceptance on 2026-10-31 loaded the real public ChatGPT page with proxy/capture enabled, verified all seven observed TLS challenges were accepted by the app-scoped CA handler, denied privileged provider IPC, and executed the real browser-session history job to an explicit signed-out result with zero imports. Hrungnir's existing same-delegate rebind and exact-host ATS pattern corrected the blank capture view; no Keychain or system trust was installed. Provider metadata now avoids Wry's unsafe URL getter during failed/in-flight navigation. This is public-page and signed-out integration evidence only; real authenticated history and generated-turn acceptance remains pending.
