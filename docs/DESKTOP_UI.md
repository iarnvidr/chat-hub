# Desktop UI preview

The desktop UI has an explicit, development-only fixture adapter for browser review. From the repository root, serve this checkout with `python3 -m http.server 8000` and open `http://127.0.0.1:8000/desktop-ui/index.html?fixture=demo`. The page labels this mode **Development fixtures — native service not connected**; it never silently substitutes fixture data in the native app or ordinary browser view. Fixture mode exercises the reader, branches, search snippets, pagination, and retryable unavailable-service state; it does not demonstrate backend integration.

The native desktop application uses the Rust/Tauri service bridge and the current library UI. Hosted PR23 debug-native run [41110436605](https://github.com/iarnvidr/chat-hub/actions/runs/41110436605), source `6b7f1f9a41daf4e9894e4ab946acb1639fa48c9d`, verifies official fixture import, library UI body, body full-text search, selection, alternate-branch detail, and persistence in the same default OS-account app-data directory across same-process use, restart, and closure. It does not verify an alternate home/data-directory override, production packaging/startup, public DMG installation, provider capture, or native Save dialog/file acceptance. Raw native IPC health status was not retained separately. The native Save commands exist in source and reuse the consistent SQLite backup and streamed JSON export APIs; JSON export is not restore. Existing targets are refused, cancellation creates no file, and normal successful receipts confirm durability after sync. Only `Error::ArchivePublished` means publication succeeded but durability is unconfirmed; the UI warns that the file exists. Do not automatically overwrite/retry or report that nothing was saved. See [known issues](../KNOWN_ISSUES.md).

Linux checks: `node --test tests/desktop_ui_*.test.cjs`; the CI workflow additionally runs the Playwright browser check using an isolated temporary install.
