# Desktop UI preview

The desktop UI has an explicit, development-only fixture adapter for browser review. From the repository root, serve this checkout with `python3 -m http.server 8000` and open `http://127.0.0.1:8000/desktop-ui/index.html?fixture=demo`. The page labels this mode **Development fixtures — native service not connected**; it never silently substitutes fixture data in the native app or ordinary browser view. Fixture mode exercises the reader, branches, search snippets, pagination, and retryable unavailable-service state; it does not demonstrate backend integration.

The native desktop application requires the Rust/Tauri service bridge. Accepted PR23 debug-native smoke evidence verifies the official fixture import, library UI body, full-text search, selection, and alternate-branch detail and persistence in the same default app-data directory across same-PID use, restart, and closure. It does not prove production packaging/startup, public DMG installation, provider capture, or native save-dialog/file acceptance. The backend source provides `backup_library` and `export_library_json` with native save handling, but that native dialog/file path remains under development pending review and authorized future Mac verification. Backup is a consistent SQLite backup, not a raw copy; JSON export is streamed, not restore. Existing targets are refused; cancellation creates no file. Normal save receipts confirm durability after successful sync. Only a post-publication durability failure (`Error::ArchivePublished`) means the file exists but durability is unconfirmed; the UI warns for that case. Do not automatically overwrite or retry it, and do not report that nothing was saved. See [known issues](../KNOWN_ISSUES.md).

Linux checks: `node --test tests/desktop_ui_*.test.cjs`; the CI workflow additionally runs the Playwright browser check using an isolated temporary install.
