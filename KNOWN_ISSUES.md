# Known issues

PR1 implements a localhost API/CLI, SQLite initialization, and a selective CONNECT TLS proxy, but is not yet an end-to-end conversation hub.

- Proxy HTTP streaming/framing and allowlist behavior are under active correction; current proxy behavior is not production-ready.
- Accepted PR23 debug-native evidence is narrow: official fixture import and library UI body, full-text search, selection, and alternate-branch detail and persistence in the same default app-data directory across same-PID use, restart, and closure. This does not verify production packaging/startup, public DMG installation, provider capture, or native save-dialog/file acceptance.
- Native library backup/export commands exist in source, but save-dialog/file acceptance is still pending review and authorized future Mac verification. Backup uses a consistent SQLite backup (not a raw database copy); JSON export is streamed and is not a restore format. Existing targets are refused without clobbering; cancellation creates no file. Normal save receipts confirm durability after successful sync. Only a post-publication durability failure (`Error::ArchivePublished`) means the file exists but durability is unconfirmed; the UI warns for that case. Do not automatically overwrite or retry it, and do not report that nothing was saved.
- The capture scope is `chatgpt.com` and its subdomains, except recognized auth/sign-in hosts. Those and all other hosts tunnel without TLS decryption. No real provider traffic has been validated.
- Proxy capture events are not ingested into SQLite. No provider extraction, data export import, conversation/message model, or usable conversation UI exists yet; these are later PRs.
- Capture through the in-app proxy is NOT yet verified on macOS. Provider interception/capture and its denial checks are advisory only; internal failure with null href/readystate is not positive capture evidence. Capture remains disabled by default, and raw native IPC health status payloads are not retained as a separate artifact; do not claim capture or a retained-status artifact. Required app launch, health, updater, DMG and signed-updater gates remain required.
- Search is currently title matching, not full-text search over conversation content.
- The API uses plaintext HTTP with bearer authentication on loopback. It is trusted-local-only, not suitable for exposure to untrusted networks or as protection from local users/processes.
- CA trust is not installed automatically; CA lifecycle and user-guided trust management need further review.
- PR2's mandatory packaged-app updater acceptance on hosted `macos-15` remains pending. The exact updater verifier accepted downloaded controlled-fixture records (healthy fixture 0.1.0→0.1.1; a tampered artifact was blocked with `signature_verification_failed`), but this is not genuine public release update evidence and does not establish genuine-baseline 0.1.1→0.2.0 or close the protected genuine-baseline ordering decision, which requires owner approval. Provider-proxy capture/ingest and undecrypted auth-tunnel evidence is advisory while macOS interception remains unverified.
- Real ChatGPT login/account behavior and downloaded-app quarantine/Gatekeeper behavior remain manual acceptance items. Do not characterize all macOS behavior as untested; the hosted macos-15 evidence gate is specific and pending.
